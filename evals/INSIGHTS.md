## What Doesn't Work
- [2026-07-08] `skill-quality.ts` must NOT strict-YAML-parse SKILL.md frontmatter: gray-matter's default js-yaml 3.15.0 throws on an unquoted `description` with `: ` (e.g. "Trigger terms: x") — valid for Claude Code — and an unguarded `matter()` lets one such file abort the whole gate. Shipped fix: a tolerant `key: value` engine (`tolerantYaml`) + per-skill `try/catch`, plus `internalLinks` strips code spans so backtick'd example links aren't checked as real refs, plus a soft-WARN on unquoted-`: ` descriptions; `evals/src/skill-quality.ts` (tolerantYaml, internalLinks, evaluate).

- [2026-07-08] A plain `tsx` probe/CLI must import runtime pieces (`runClaude`, etc.) from their submodule (e.g. `evals/src/runtime/run-claude.js`), NOT from the barrel `evals/src/index.js`: the barrel re-exports the case DSL, which imports `vitest`, and importing vitest outside its runner throws `Error: Vitest failed to access its internal state`. The barrel is only for `*.eval.ts` files run under vitest; `evals/src/index.ts`.

- [2026-07-08] On Windows `eval:repeat`/`eval:delta`/`eval:benchmark` all die with `spawn pnpm ENOENT` *before* any model call — `run-vitest.ts` spawned `pnpm` (a `.cmd` shim) via `spawn()`/`execFileSync()` with no shell, and `countTests` swallowed it (prints `? test case(s)`); `eval:quality`/`eval`/`eval:skills` run `tsx`/`vitest` directly so were unaffected. Fix: `shell:true` on both calls in `evals/src/run-vitest.ts` (runVitestOnce, countTests) — resolves `pnpm.cmd` via cmd.exe on Windows (`/bin/sh` on POSIX); Node 24 then emits a benign DEP0190 (shell args concatenated not escaped — safe for these fixed internal args).

- [2026-07-08] Content-tier eval practices must only assert what SKILL.md itself teaches: `skillContent()` injects SKILL.md plus `references/*.md` from a `references/` DIRECTORY only — flat `references.md`/`examples.md` files at the skill root (e.g. onion-architecture) are never injected, despite the README's "full payload" wording; `evals/src/artifacts/load.ts` (skillContent).

- [2026-07-09] A negative practice ("does NOT flag X") is unprovable to the verbatim-evidence judge when the model stays silent about clean code — the case prompt must force the mention ("If a part already follows best practice, say so explicitly"). Likewise a practice must not be narrower than the skill it tests: accept every fix the skill canonically recommends (e.g. refine returning false OR superRefine+ctx.addIssue), else a skill-correct answer fails; `evals/skills/zod/zod.cases.ts` (REVIEW_TASK).

- [2026-07-09] A false-positive-control practice ("does NOT flag X") is only valid if the "safe" fixture pattern is FLAWLESS by the skill's OWN rules — not just free of the one flaw you had in mind. Hit twice: security `enrichNote` carried an accidental IDOR-on-read; drizzle `consumeQuota` used `tx.rollback()` (endorsed by SKILL Example 3) but WITHOUT the try/catch the skill's Constraints section demands, so the model correctly flagged the rollback-handling gap. Before asserting "must not be flagged", audit the pattern against every rule the skill teaches; if in doubt, use a trivially-correct control (e.g. a plain `db.transaction` with no rollback); `evals/skills/security/fixtures/notes-controller.js`, `evals/skills/drizzle-orm-patterns/fixtures/review-writer.ts`.

- [2026-07-09] Keep each judged practice single-quote-provable — one verbatim quote must be able to prove it. A 4-5-clause practice (detect + exploit narrative + fix A + fix B + severity) is flaky: no single quote covers it all, so the judge FAILs it with empty evidence even when the model clearly did the work (confirmed twice — zod guidance, security injection where the exploit was quoted under a DIFFERENT passing practice yet the composite command-injection practice failed). Split into ≤2-clause practices ("flags X — and the fix does Y"); put severity/structure in their own practice; `evals/skills/security/security.cases.ts`, `evals/skills/zod/zod.cases.ts`.

- [2026-07-09] A case failing with `Reached maximum number of turns (1)` while its own trace says `ok (1 turns)` is the JUDGE hitting its limit, not the task: `llmJudge` runs `runContent(..., maxTurns:1)` — the only turn-capped call — and it transiently trips (retry usually clears it). - [2026-07-12] A `-t` filter with a PIPE-alternation regex (`-t "a|b"`) CRASHES `eval:repeat` on Windows — `run-vitest`'s `shell:true` hands the concatenated argv to cmd.exe, which splits on `|` and treats the second alternative as its own command (`'does' is not recognized …`, 0 records, "run crashed"). SPACES in `-t` are fine (`-t "flags both violations"` works); the `|` is the problem. To scope to multiple cases run separate substring `-t` invocations, or a full no-`-t` run; `evals/src/run-vitest.ts` (runVitestOnce, shell:true).

- [2026-07-10] Loading `OPENROUTER_API_KEY` for a local content-tier eval by `source`/`. file` on a key-file LEAKS the key in Git Bash: a file saved UTF-8-WITH-BOM (PowerShell's default) makes `sh` treat the first line as a command and echo the whole `OPENROUTER_API_KEY=sk-or-...` into the `command not found` error (a leaked key must then be rotated). Read the value WITHOUT executing instead — `export OPENROUTER_API_KEY="$(sed -e '1s/^\xEF\xBB\xBF//' -e 's/\r$//' FILE | grep -m1 '^OPENROUTER_API_KEY=' | cut -d= -f2-)"` — and save key-files with `utf8NoBOM`.
